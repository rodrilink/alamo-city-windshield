## Method note — why the earlier regex parses disagreed

Requirement declarations are recorded under **three different frontmatter key names**, in two different YAML shapes:

| Key name | Used by | Shape |
|---|---|---|
| `requirements_satisfied` | 01-01 | inline flow list |
| `requirements-completed` | most plans (03-*, 04-03..04-11, 05-02..05-09, 06-01..06-07) | inline flow list |
| `requirements:` | 02-02, 04-01, 04-02, 04-08, 04-12, 05-01 | 02-02 uses a block list; the rest inline |

`NAV-01` looked orphaned because `01-04-SUMMARY.md` declares it under `requirements-completed` (hyphenated), which a pattern anchored on `requirements_completed` (underscored) misses. Additionally, **8 SUMMARYs carry no requirements key at all**: 01-02, 01-03, 01-05, 02-01, 02-03, 02-04, 06-05. Any regex-only pass will therefore under-count, and the count will vary with which key spelling the pattern happens to match. Everything below comes from reading the files and the source, not from pattern matching.

## Security Findings

### Highest-severity finding in this audit (not a requirement gap)

**Middleware fails open when Supabase env vars are absent.** src/lib/supabase/middleware.ts lines 8-12:

```ts
const supabaseUrl = process.env.NEXT_PUBLIC_SUPABASE_URL
const supabaseAnonKey = process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY
if (!supabaseUrl || !supabaseAnonKey) {
  return NextResponse.next({ request })
}
```

If either variable is unset, the function returns **before** getUser() and **before** the /admin/* redirect. Every admin route is then served to anonymous visitors, with no error and no log line. The in-code comment says the env vars are always set on Vercel in production - that is an assumption, not an enforcement.

This matters right now specifically because of FDN-06: since the Vercel project does not exist yet, the first deploy is exactly the moment a missing or mistyped env var is most likely. Recommend failing closed (redirect /admin/* to /admin/login when unconfigured) or throwing at module load when NODE_ENV is production. Close this before the first deploy, not after.
