<objective>
Build the two pure, dependency-free modules this phase's correctness rests on: server-side slot generation from `BUSINESS.hours`, and a timezone-correct "now" in `America/Chicago`.

Purpose: D-02's rule — a slot is offered only if it ends at or before closing — is a **general invariant**, not a Saturday special case. It must hold for any future change to `BUSINESS.hours` with no new code. D-06 forbids trusting the browser clock for "is this slot in the past", so the server must decide, in Central time, independent of the host's timezone (Vercel runs UTC). Both are pure functions with exact expected outputs, which makes them the ideal TDD target and the only part of this phase testable before the database and packages land.

Neither module needs any of the five packages from plan `04-01` — `Intl.DateTimeFormat` covers the timezone work with zero dependencies (verified live in this repo's Node 24 runtime during research). That is why this plan runs in Wave 1, in parallel with both human gates.

Output: `src/lib/booking/slots.ts`, `src/lib/server-time.ts`, and their Vitest suites.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser clock → booking availability decision | A wrong or deliberately manipulated client clock must never influence which slots are bookable |
| client-submitted `appt_time` → database insert | Any time value reaching the insert must be provably a member of the legal generated slot list |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-03-01 | Tampering | Client clock manipulated to re-open an already-passed slot | mitigate | D-06: `getBusinessNowParts()` computes "now" server-side via `Intl.DateTimeFormat` with an explicit `America/Chicago` timeZone; `import 'server-only'` makes a client-side import a build error |
| T-04-03-02 | Tampering | Off-grid `appt_time` such as `03:00` submitted directly | mitigate | `generateSlotsForDate` is the single authority for what times exist; plan `04-05` re-runs it inside the Server Action so the same function backs both the displayed list and the D-15 server re-validation, making disagreement impossible |
| T-04-03-03 | Tampering | Slot allowed to run past closing time | mitigate | D-02 encoded as the loop inequality `start + SLOT_DURATION_MINUTES <= closeMinutes`, pinned by a regression test asserting Saturday excludes `13:30` |
| T-04-03-04 | Information Disclosure | Business hours or slot times leaking sensitive data | accept | `BUSINESS.hours` already renders publicly in the site footer and slot availability is intentionally public; no secret value exists in this module, unlike `pricing.ts` |
</threat_model>
