<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anonymous browser → createContact Server Action | Unauthenticated public input crosses into a service-role database write |
| client-built URL → /book | Any value placed in the CTA href is attacker-controllable on the receiving page |
| Client Component → server-only modules | The pricing formula and decode internals must never reach the browser bundle |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-07-01 | Tampering | Vehicle identity or pricing smuggled through the `/book` CTA URL | mitigate | D-19: only the raw VIN is appended, gated by `isValidVin` and URL-encoded; `/book` re-decodes server-side (plan `04-06`) and never trusts URL-supplied vehicle data |
| T-04-07-02 | Denial of Service | Automated contact-form spam | mitigate | CONT-03/D-14 honeypot rendered here and enforced server-side in `04-05` before any database call; rate limiting remains accepted residual risk per T-04-05-04 |
| T-04-07-03 | Information Disclosure | Pricing formula reaching the browser via the contact page | mitigate | `ContactVinSearch` consumes precomputed `estimates` from `/api/vin/[vin]` and imports neither `@/lib/pricing` nor `@/lib/vin`; the `server-only` fence makes any such import a build error |
| T-04-07-04 | Input Validation | Malformed VIN submitted to the decode endpoint | mitigate | Client-side `VIN_REGEX` check before fetch, plus the existing server-side `isValidVin` gate in `/api/vin/[vin]` which returns the `invalid` status — the authoritative check remains server-side |
| T-04-07-05 | Spoofing | A transient contact-submit failure presented as permanent | mitigate | `CONTACT_COPY`'s error message is distinct from the success message and includes `BUSINESS.phone`, preserving entered values so the customer can retry |
</threat_model>
