<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser form input → Zod schema | `email`/`password`/`confirmPassword` arrive untrusted from a client form and are re-validated server-side inside the Server Action |
| Server Action → browser (returned state) | `AddUserActionState.generatedPassword` carries a real credential back to the browser exactly once (D-12) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-03-01 | Information Disclosure | `loginSchema` password rule | mitigate | No `min(8)` on the login password. A length-validation error would distinguish "not a valid password shape for this system" from "wrong password", giving an attacker a signal. Only `addUserSchema` (account creation) carries `min(8)` |
| T-05-03-02 | Information Disclosure | `ADMIN_COPY.loginGenericError` | mitigate | Single fixed string for all credential failures, containing no interpolation and no email, so a wrong password and a non-existent account are indistinguishable — matching `signInWithPassword`'s own documented behavior. Asserted by acceptance criteria |
| T-05-03-03 | Information Disclosure | `AddUserActionState.generatedPassword` | mitigate | Typed as optional and commented in `src/types/admin.ts` as returned exactly once and never logged; plan `05-08` enforces the no-log rule at the Server Action that populates it |
| T-05-03-04 | Denial of Service | `isLastAdminAttempt` off-by-one permitting removal of the final admin | mitigate | Predicate uses `<= 1` rather than `=== 1`, so a `0` count also blocks; a dedicated unit test asserts `isLastAdminAttempt(0) === true`. Locking out every admin is recoverable only via the Supabase dashboard (D-08 leaves no reset flow) |
| T-05-03-05 | Elevation of Privilege | Guard predicates bypassable by hiding UI only | mitigate | Predicates are pure and exported so plan `05-08` can call them inside `removeUserAction` before any `deleteUser()`; D-10 forbids UI-only enforcement |
| T-05-03-06 | Information Disclosure | Failed dashboard query rendered as legitimate empty data | mitigate | `ADMIN_COPY.queryFailedMessage` is a separate string from `dashboardEmptyStateHint`, and `DashboardReadResult` makes `ok: false` structurally distinct from zero rows (RESEARCH.md Pitfall 3) |
</threat_model>
