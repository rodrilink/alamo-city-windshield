<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Postgres rows → RSC payload → browser | Every column rendered in a card, chart or table is serialized into the page payload delivered to the browser |
| Server Component → Client chart props | The `DailyBucket[]` arrays cross into client-executed code |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-07-01 | Information Disclosure | Customer PII (name, phone, address, VIN) rendered on the dashboard | mitigate | The whole `/admin` route sits behind the middleware `getUser()` guard (AUTH-03) and every read runs under RLS as the authenticated admin. The tables render only the columns the query module selected; `honeypot` is asserted absent and long `message` text is truncated rather than dumped |
| T-05-07-02 | Information Disclosure | Raw query error text surfacing on screen | mitigate | Components branch on the `DashboardReadResult` discriminant and render `ADMIN_COPY.queryFailedMessage`; they never receive or render Supabase error objects, which stay in the server log |
| T-05-07-03 | Information Disclosure | A failed read rendering as legitimate "no data yet", hiding a real fault | mitigate | Failure and empty are separate branches with different `ADMIN_COPY` strings in every card, chart and table, asserted by grep (RESEARCH.md Pitfall 3) |
| T-05-07-04 | Elevation of Privilege | Server-only query module pulled into a client bundle via a chart import | mitigate | `dashboard-queries.ts` carries `import 'server-only'`, so such an import is a build error; acceptance criteria additionally assert no chart component imports it or `@/lib/supabase/*` |
| T-05-07-05 | Tampering | Unintended write path from a read-only surface | mitigate | D-15 forbids row actions; grep asserts no `onClick`, `onSubmit`, `<button>` or `href` exists in either table, so the dashboard exposes no mutation surface at all beyond logout |
| T-05-07-06 | Information Disclosure | Fabricated metrics misrepresenting site activity to the owner | mitigate | D-02 forbids any invented number. The two analytics-sourced cards show a real `0` with `trackingStartsHint`, and the two `analytics_events` charts show the explicit D-01 empty state naming Phase 6 as when tracking arrives |
| T-05-07-07 | Information Disclosure | VIN re-decoding leaking internal page data to a third party (NHTSA) | mitigate | ADMIN-07 renders the denormalized `vehicle_desc` written by Phase 4 (D-12); grep asserts no NHTSA or VIN-decode import exists in the appointments table, so no outbound third-party call originates from an authenticated internal page |
</threat_model>
