<objective>
Fire a `vin_search` event on every successful VIN decode (ANLY-03) from the single Route Handler that already owns the outcome decision — in **both** of its success branches.

Purpose: `/api/vin/[vin]` is D-13's single insertion point. It covers both existing callers (`EstimateSection.tsx` and `ContactVinSearch.tsx`, which each `fetch('/api/vin/...')`) plus any future one, and cannot be skipped by a caller who forgets. It already holds the validated, normalized VIN past the `isValidVin` gate and already knows the exact outcome, so nothing needs re-deriving.

⚠ **The critical trap (D-15):** this route has TWO success `return NextResponse.json(...)` statements. The first is a `vin_cache` hit early-return at Step 2 that never calls NHTSA — easy to miss. If the event lands in only the post-NHTSA branch, the ADMIN-04 chart will *drop* as caching improves, inverting the metric's meaning. From the user's side a cache hit is an identical successful search; the metric measures user demand.

Output: one modified file, `src/app/api/vin/[vin]/route.ts`, with two call sites added and no behavior change to any response.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public internet → `/api/vin/[vin]` | Unauthenticated GET reachable directly with any path segment (`curl /api/vin/anything`). This is the phase's pre-existing trust boundary with the outside world (VIN-01, threat T-03-01). |
| route handler → `analytics_events` (service-role) | `trackServerEvent` writes with an RLS-bypassing identity, server-side only. |
| a caller-supplied VIN → the `analytics_events.vin` column | An externally supplied 17-character string is persisted. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-03-01 | Tampering | Unvalidated input reaching the `vin` column | mitigate | Both insertion points sit strictly downstream of the Step 1 `isValidVin` gate, which returns HTTP 400 before any network or database call. The value passed is the normalized `rawVin.trim().toUpperCase()` local, so only a 17-character VIN-charset string can reach the column. Task 1 forbids passing `cached.vin` or any other unvalidated variant. |
| T-06-03-02 | Information disclosure | Storing the raw VIN | accept | D-03 stores the raw 17-character VIN, matching existing precedent — `bookings.vin`, `contacts.vin`, and `vin_cache` (which stores the VIN *plus* the full NHTSA payload) already persist raw VINs. The `vin` column on `analytics_events` exists for exactly this. Reads are gated by `admin_select_analytics` = `USING (auth.role() = 'authenticated')`, so only logged-in admins can retrieve rows. Accepting a fourth VIN store introduces no new class of exposure; revisit only alongside a project-wide VIN-retention decision. |
| T-06-03-03 | Information disclosure | Tracking failure leaking diagnostics into the response | mitigate | `trackServerEvent` returns `void` and logs to the server console only. The route's existing rule — `detail`/`reason` are server-side diagnostics that must never reach the response body (T-03-08) — is preserved: Task 1 forbids branching on the tracking call or altering any response body. |
| T-06-03-04 | Denial of service | Unauthenticated endpoint now performing a database write per request | mitigate | The write occurs only on the two *success* paths, which for a cache hit already performed a `vin_cache` read and for a fresh decode already performed an NHTSA call plus a `vin_cache` write. Garbage input short-circuits at the `isValidVin` gate with zero writes, so the cheapest-to-forge requests remain the cheapest to serve. Net added cost is one same-region insert on an already-expensive path. |
| T-06-03-05 | Repudiation | Silent under-count from implementing only one branch | mitigate | This is the plan's headline risk (D-15). Mitigated by three acceptance criteria that independently assert the call count is exactly 2, that one call precedes `cached: true`, and that one precedes `cached: false`. Also called out in the code comment at the cache-hit site so a future editor cannot remove it unknowingly. |
| T-06-03-06 | Repudiation | Over-count from a second insertion point | mitigate | D-16 excludes `book/page.tsx`'s server-side re-decode, which bypasses this route by calling `decodeVin`/`readVinCache` directly. Enforced by an acceptance criterion asserting zero `trackServerEvent` references in that file, and by the repo-wide call-site enumeration. |
| T-06-03-SC | Tampering | npm/pip/cargo installs | n/a | This plan installs no packages. |
