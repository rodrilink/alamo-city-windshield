<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → `analytics_events` (anon key, RLS `WITH CHECK (true)`) | `trackBrowserEvent` writes from untrusted client code with an anonymous, unauthenticated identity. Any visitor can craft the same insert directly with the public anon key. |
| Server Action / Route Handler → `analytics_events` (service-role key) | `trackServerEvent` writes with an RLS-bypassing identity. The key never reaches the browser; `admin.ts`'s `import 'server-only'` fence enforces this at build time. |
| `analytics_events` → admin dashboard | Rows written by either path are later read and rendered by the Phase 5 dashboard for an authenticated admin. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01-01 | Tampering | `trackBrowserEvent` anon insert path | accept | The `public_insert_analytics` policy (`WITH CHECK (true)`) is pre-existing from Phase 1 and was written for exactly this use.
