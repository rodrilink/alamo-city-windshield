## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → `GET /api/vin/[vin]` and `GET /api/estimate` | Client-supplied values leave the browser; the server re-validates independently |
| server response → rendered DOM | NHTSA-originated strings (make, model) are rendered as text |
| server module graph → client bundle | Both files here are `'use client'` and ship in full |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | Client-side VIN validation in `EstimateSection.tsx` | mitigate | The client check is a UX affordance only and is explicitly NOT the security control — the authoritative gate is `isValidVin` inside the Route Handler (plan `03-06`). Importing `VIN_REGEX` from `@/types/vehicle` rather than redeclaring it prevents the two checks from drifting. The `'invalid'` status branch exists precisely because the server can reject something the client accepted. |
| T-03-12 | Information Disclosure | `make`, `model`, and the composed `headline` rendered from the NHTSA response | mitigate | All values render as JSX text children, so React escapes them. No `dangerouslySetInnerHTML` anywhere — asserted by `grep -c "dangerouslySetInnerHTML" src/components/home/*.tsx` returning 0. |
| T-03-03 | Information Disclosure | Both client components | mitigate | Neither may import `@/lib/pricing`; a violation is a Next.js build failure via that module's `server-only` marker, and `npm run build` is in the automated verify. Acceptance greps additionally assert no pricing literal appears in executable lines, so every displayed number provably arrives from the API response. |
| T-03-08 | Information Disclosure | Error text surfaced to the user | mitigate | Both fetch call sites catch and replace failures with fixed copy from `ESTIMATE_COPY` — `unreachableMessage` and a generic year-check message. No `error.message`, HTTP status text, or response body is rendered. The D-17 catch-all deliberately shows the fallback form rather than any diagnostic. |
| T-03-17 | Denial of Service | Rapid repeated submissions from one browser driving proxy calls | mitigate | The submit button and input are disabled for the duration of the in-flight request (D-08), which prevents accidental double-submission from the UI. This does not constrain a non-browser caller — see T-03-15 in plan `03-06`, where proxy rate limiting is an accepted, developer-deferred residual risk. |
