<!-- Verified during planning by reading the installed @base-ui/react type definitions. Most shadcn/ui documentation online assumes Radix and will mislead you here. -->

**This project's shadcn primitives wrap `@base-ui/react`, NOT Radix.** `src/components/ui/button.tsx` line 1 imports from `@base-ui/react/button`; `src/components/ui/sheet.tsx` imports from `@base-ui/react/dialog`. `@base-ui/react` is version 1.3.0. Base UI uses a `render` prop where Radix uses `asChild`. Do not reach for `@radix-ui/*` — it is not a dependency.

**`@base-ui/react/radio-group` and `@base-ui/react/radio` are already installed with no shadcn wrapper generated.** Verified exports:
- `@base-ui/react/radio-group` exports `RadioGroup`, generic over `Value`. Relevant props: `value?: Value`, `defaultValue?: Value`, `onValueChange?: (value: Value, eventDetails) => void`, `name?: string`, `disabled?: boolean`. Renders a `<div>` with radiogroup semantics and arrow-key navigation.
- `@base-ui/react/radio` exports a `Radio` namespace containing `Radio.Root` and `Radio.Indicator`. `Radio.Root` is generic over `Value`, requires a `value: Value` prop, and renders a `<span>` plus a hidden `<input>` beside it. Its state type includes a boolean `checked`.

**Base UI's `className` accepts a function of state.** The type is `className?: string | ((state: State) => string | undefined)`. Use the function form on `Radio.Root` and read `state.checked` to style the selected segment. This is type-guaranteed from the `.d.ts`, unlike relying on a `data-checked` attribute selector. Do not use `Radio.Indicator` — a segmented control shows selection through the segment's own background, not a separate dot.

**Prefer `RadioGroup` over `ToggleGroup`.** `ToggleGroup`'s `value` prop is `readonly Value[]` (an array, even in single-select mode) and its `onValueChange` yields an array, which is awkward for a single-select and gives no radiogroup semantics. `RadioGroup` yields a scalar and provides the accessibility semantics for free.

**Existing shadcn wrapper conventions to mirror** (from `src/components/ui/button.tsx`, read it in full):
- `import { cva, type VariantProps } from "class-variance-authority"` and `import { cn } from "@/lib/utils"`
- Every primitive sets `data-slot="…"` on its root element
- `className` from the caller is merged last via `cn(base, className)`
- `defaultVariants` declared on the `cva` config

**Card composition precedent:** consumers in this repo only ever compose `Card` + `CardHeader`/`CardContent` + `CardTitle`. `CardFooter`, `CardAction`, and `CardDescription` exist in `card.tsx` but are unused anywhere — do not introduce them without precedent.

**Palette constraint (Phase 1 D-05):** strictly white, red, and black. No amber or yellow exists in the theme, so the ADAS note and the D-18 message must be differentiated by icon and layout rather than by warning colour. Use `text-muted-foreground` for informational text, `bg-primary`/`text-primary-foreground` for the selected segment (brand red `#B91C1C` with white text), and `text-destructive` only for genuine validation errors.

**Icon convention (`lucide-react` 1.8.0, already installed):** named imports directly from `lucide-react`; size with Tailwind `h-4 w-4` for inline text-adjacent icons; pair with `aria-hidden="true"` when adjacent text already conveys the meaning (precedent: `src/components/layout/TopNav.tsx` line 53).

**Existing `src/lib/constants.ts`** exports a single `BUSINESS` object declared `as const`, with `phone` (display string, e.g. `(210) 555-0100`) and `phoneHref` (a `tel:` URI) always paired. Never hardcode the phone number again.

**Height constraint:** this card renders inside a `snap-start snap-always h-dvh` section within a `snap-y snap-mandatory` container. Anything that grows past `h-dvh` breaks the snap experience — decision D-07 (swap the form for the result inside the same card) exists specifically to avoid this. Keep spacing compact.
