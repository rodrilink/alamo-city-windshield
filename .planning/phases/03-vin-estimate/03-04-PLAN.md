<objective>
Build the server-side decode layer: a service-role Supabase client, failure-tolerant `vin_cache` access, and the NHTSA vPIC call whose classification drives the three deliberately-distinct failure paths D-17, D-18, and D-19.

Purpose: This is where the phase's hardest correctness problem lives. `ErrorCode` looks like a pass/fail flag and is not one — a real Ford F-150 VIN with a deliberately wrong check digit returns `ErrorCode: "1"` alongside a complete `Make`/`Model`/`BodyClass`/`ModelYear`. Branching on `ErrorCode` would show real customers the "check your VIN characters" message. Field presence is the reliable classifier. Getting this wrong collapses D-17 and D-18 into one path, which CONTEXT.md calls out as a regression rather than a simplification.

Output: `src/lib/supabase/admin.ts`, `src/lib/vin-cache.ts`, `src/lib/vin.ts`, `src/lib/vin.test.ts`.
</objective>

<!-- All of the following was verified by live probe during planning against the real NHTSA endpoint and the real installed packages. Treat it as authoritative over any general documentation. -->

**Endpoint and response shape.** `GET https://vpic.nhtsa.dot.gov/api/vehicles/decodevinvalues/{vin}?format=json` returns top-level keys `Count`, `Message`, `SearchCriteria`, `Results`. `Results` is an **array of length 1** whose single element is a flat object of **154 fields**. The access path is therefore `body.Results[0]`.

**NHTSA always returns HTTP 200.** Every VIN shape probed — valid, bad-check-digit, all-Z garbage, too short, invalid characters — returned 200. A non-2xx status therefore means a genuine service outage, and must route to `unreachable` (D-17), never to `not-found` (D-18).

**`ErrorCode` is advisory, not binary.** Two live captures:
- VIN `1FTFW1E85NFA12345` → `ErrorCode: "1"`, `ModelYear: "2022"`, `Make: "FORD"`, `Model: "F-150"`, `BodyClass: "Pickup"`. Non-zero code, fully usable data.
- VIN `ZZZZZZZZZZZZZZZZZ` → `ErrorCode: "1,7,11,400"`, `ModelYear: ""`, `Make: ""`, `Model: ""`, `BodyClass: ""`. Comma-joined multi-code string, no usable data.

`ErrorCode` is an unstructured comma-joined list with no fixed cardinality. **Do not parse it for branching.** It may be logged. Empty fields arrive as empty strings, not `null` or `undefined`.

**Error shapes for the timeout branch** (Node v24.13.0, verified):
- `AbortSignal.timeout(6000)` exceeded → throws a `DOMException` whose `name` is `'TimeoutError'`
- Unresolvable host / network failure → throws a `TypeError` whose `message` is `'fetch failed'` and whose `cause.code` is e.g. `'ENOTFOUND'`

**Complete BodyClass inventory.** NHTSA's `BodyClass` variable has 71 possible values (pulled live from `GetVehicleVariableValuesList/BODY%20CLASS`). The three buckets and their exact strings:
- `car`: `Sedan/Saloon`, `Coupe`, `Convertible/Cabriolet`, `Hatchback/Liftback/Notchback`, `Wagon`, `Roadster`, `Limousine`
- `suv-truck`: `Sport Utility Vehicle [SUV]/Multipurpose Vehicle [MPV]`, `Crossover Utility Vehicle [CUV]`, `Pickup`, `Truck`, `Sport Utility Truck [SUT]`
- `van-oversized`: `Van`, `Minivan`, `Cargo Van`, `Step Van/Walk-in Van`, `Motorhome`, `Bus`, `Bus - School Bus`

Every other value of the 71 is **unmappable** and must trigger D-19. That set includes the empty string, all 16 `Incomplete*` variants, `Truck-Tractor`, `Trailer`, `Streetcar/Trolley`, `Low Speed Vehicle [LSV]/Neighborhood Electric Vehicle [NEV]`, all 16 `Motorcycle - *` variants, all `Off-Road Vehicle - *` variants, `Ambulance`, `Street Sweeper`, and `Fire Apparatus`. Do NOT enumerate the unmappable set in code — implement it as "not in any of the three allow-lists", which is closed against future NHTSA additions.

**`vin_cache` is RLS-enabled with zero policies** (`supabase/migrations/20260412000000_initial_schema.sql` lines 116-122). Anon and authenticated roles get zero access by design. Only the service-role client can read or write it. `vin_cache.vin` carries a `UNIQUE` constraint (line 108), so two concurrent first-time lookups of the same VIN will collide on insert.

**Existing Supabase client convention** — mirror it exactly. `src/lib/supabase/server.ts` and `src/lib/supabase/client.ts` are both bare factory functions named `createClient`, reading env vars via `process.env.X!` non-null assertion, with no class wrapper, no DI container, and no environment-variable retriever abstraction. This project has no `EnvironmentVariablesRetriever` — direct `process.env` access is the established local convention.

**Naming collision warning:** both existing files export the bare name `createClient`. The new admin factory MUST be named `createAdminClient` so a file importing two Supabase clients does not need an aliased import.
