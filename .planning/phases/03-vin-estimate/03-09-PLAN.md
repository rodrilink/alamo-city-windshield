<objective>
Close the single UAT gap from test 10: on a manual-entry result, switching the
vehicle-type selector reprices correctly ($405 – $495 for Van) but the headline
stays pinned to "2015 Car".

Root cause (03-UAT.md): `EstimateResult` receives `headline` as a precomputed
string prop, while `sizeBucket` is separate live state. Pricing reads the live
state (`estimates[sizeBucket][glassType]`), so it reprices; the headline is a
frozen string that `EstimateSection` built once from `chosenBucket` at submit
time.

Purpose: make the displayed vehicle-type label derive from the same live state
that drives pricing, so label and price can never disagree.
Output: fixed manual-path headline, decoded-VIN headline explicitly protected,
and a render regression test that fails if the two ever diverge again.

Scope guard — do NOT do any of these:
- Do not refactor `EstimateResult` beyond the headline derivation.
- Do not change the decoded-VIN headline behavior. A real make/model
  ("2022 Ford F-150") must NOT follow the size-bucket selector.
- Do not touch `src/lib/pricing.ts`, the Route Handlers, or `src/lib/vin.ts`.
- Do not re-do any work from plans 03-01 through 03-07.
</objective>
