# Summary: Rename component files to kebab-case

## What changed

32 files under `src/components/` were PascalCase (`HeroSection.tsx`,
`TopNav.tsx`, …) while the rest of `src/` was already lowercase. All 32 are now
kebab-case, and the 44 import specifiers referencing them were rewritten to
match.

42 files changed: 32 renames + 22 files with import-line edits (some files are
both).

## Scope decision

**Filenames only.** Exported symbols are deliberately unchanged — `HeroSection`,
`TopNav` and the rest stay PascalCase. Lowercasing them would break React: JSX
treats a lowercase tag as a DOM element, so `<heroSection />` would silently
render an unknown HTML element rather than the component. This was put to the
user, who chose the filenames-only scope.

`.planning/` docs were also offered and excluded.

## The `core.ignorecase` hazard

This repo has `core.ignorecase=true` (Windows). A direct
`git mv HeroSection.tsx hero-section.tsx` can be recorded as a **no-op** —
leaving the index holding the old name while the worktree holds the new one.
That builds fine locally and then fails on case-sensitive CI/Vercel (Linux),
which is the worst possible failure shape: invisible until deploy.

Every rename therefore went through a temp name:

```
git mv X.tsx __tmp_rename__ && git mv __tmp_rename__ x.tsx
```

Confirmed git recorded **32 `R` entries**, not delete+add and not silently
skipped.

plus a successful build covers the failure mode that matters.
