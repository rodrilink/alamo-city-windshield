# Quick Task: Add a Home option to the admin nav

## Problem

The admin shell's navigation (`AdminSidebarNav`) offers only Dashboard and
Users. There is no way to get back to the public site from inside the admin
tool without editing the URL by hand.

## Decision (from discussion)

The request named `/home`, but no such route exists — the public home page is
`/` (`src/app/(public)/page.tsx`), and `NAV_LINKS` in `src/lib/constants.ts`
already labels `/` as "Home". So: add a third nav option labeled **Home**
pointing at **`/`**.

Rejected: creating a real `src/app/(public)/home/page.tsx` route (a second URL
for the same page, duplicate content unless it just redirects); labeling it
"Back to site" (user chose the plainer "Home" wording, consistent with
`NAV_LINKS`).

## Tasks

### T-1: Add the nav label to the admin copy module

**Files:** `src/lib/constants.ts`

**Action:** Add `navHomeLabel: 'Home'` to `ADMIN_COPY` alongside
`navDashboardLabel` and `navUsersLabel`, per the existing D-14 note that
sidebar nav labels live in the copy module rather than inline.

**Verify:** `ADMIN_COPY.navHomeLabel` resolves.

**Done:** The label is defined in one place with the sibling nav labels.

### T-2: Render the Home link in the shared admin nav

**Files:** `src/components/layout/AdminSidebar.tsx`

**Action:** Add a `<Link href="/">` entry to `AdminSidebarNav` using
`ADMIN_COPY.navHomeLabel`, matching the existing links' classes, wiring
`onClick={onNavigate}` so the mobile drawer still closes on tap, and carrying a
`data-testid="link-admin-home"` per the project's test-id conventions.

Because both the desktop rail and the mobile drawer render `AdminSidebarNav`,
this single edit covers both viewports — no change needed in
`AdminMobileNav.tsx` or the dashboard layout.

Place it last in the nav group so the primary admin destinations (Dashboard,
Users) stay first and the leave-the-tool link reads as secondary.

**Verify:** `npx tsc --noEmit`, `npm run lint`, `npm test`, `npm run build`.

**Done:** Home appears in both the desktop rail and the mobile drawer, and
navigates to `/`.

## Must-haves

- The link is added once, in the shared `AdminSidebarNav` — not duplicated per
  viewport.
- The mobile drawer still closes when the new link is tapped.
- Dashboard and Users links, the admin email, and logout are unchanged.
- No new route and no new dependency.
- The dashboard layout stays a Server Component.
