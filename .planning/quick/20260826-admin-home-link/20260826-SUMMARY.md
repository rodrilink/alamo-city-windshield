# Summary: Add a Home option to the admin nav

## What changed

The admin shell's navigation offered only Dashboard and Users, with no way back
to the public site short of hand-editing the URL. A third nav option, **Home**,
now points at the public site root `/`.

Because the previous quick task extracted the nav markup into a shared
`AdminSidebarNav`, this was a single edit that covers both the desktop rail and
the mobile drawer — the extraction paid off immediately.

## Files

| File | Change |
|------|--------|
| `src/lib/constants.ts` | Added `navHomeLabel: 'Home'` to `ADMIN_COPY`, beside the sibling nav labels, per the D-14 note that sidebar labels live in the copy module. |
| `src/components/layout/AdminSidebar.tsx` | Added a `<Link href="/">` to `AdminSidebarNav` with `onClick={onNavigate}` and `data-testid="link-admin-home"`, placed last in the nav group. |

## Decisions

- **The request named `/home`, but no such route exists.** The public home page
  is `/` (`src/app/(public)/page.tsx`), and `NAV_LINKS` already labels `/` as
  "Home". Confirmed with the user, then pointed the new option at `/`.
- **Rejected creating a real `/home` route** — it would be a second URL for the
  same page, duplicate content unless it merely redirected.
- **Rejected the "Back to site" wording** — user chose the plainer "Home",
  consistent with how `NAV_LINKS` names the same destination.
- **Placed last in the nav group** so the primary admin destinations stay first
  and the leave-the-tool link reads as secondary.
- **`onNavigate` wired through** so the mobile drawer still dismisses itself on
  tap, matching the sibling links.
