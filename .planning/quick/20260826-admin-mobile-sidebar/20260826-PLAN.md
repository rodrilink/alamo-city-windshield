# Quick Task: Collapse the admin sidebar on mobile

## Problem

`src/app/(admin)/admin/(dashboard)/layout.tsx` renders `AdminSidebar` as a
permanently visible `<aside className="... w-64 shrink-0 ...">` inside a
`flex min-h-screen` row. On a narrow viewport that fixed 256px rail consumes
most of the screen, squeezing the dashboard charts and the users table into an
unusably narrow column. There is no way to dismiss it.

## Decision (from discussion)

Hamburger + slide-in drawer:
- Below `md`, the persistent rail is hidden and a compact top bar with a
  hamburger button appears.
- Tapping the hamburger opens the existing `src/components/ui/sheet.tsx` as a
  `side="left"` drawer containing the same nav links, admin email, and logout.
- The drawer closes when a nav link is tapped.
- At `md` and up, behaviour is unchanged: the static rail, no top bar, no
  hamburger.

Rejected: icon-only rail (drops the email, needs new iconography), horizontal
top nav (does not scale past two links).

## Tasks

### T-1: Extract the sidebar body into a shared, reusable inner component

**Files:** `src/components/layout/AdminSidebar.tsx`

**Action:** Split `AdminSidebar` so the nav links + email + logout markup lives
in one place and is rendered by both the desktop rail and the mobile drawer.
Add an optional `onNavigate` callback the drawer passes to close itself on link
tap; the desktop rail omits it. Keep the existing `data-testid` values
(`link-admin-dashboard`, `link-admin-users`, `text-admin-email`) on the single
rendered instance per viewport so tests keep resolving one element.

**Verify:** `AdminSidebar` still exports a component accepting `adminEmail`.

**Done:** The link/email/logout markup is written once, not duplicated.

### T-2: Add the mobile drawer + hamburger trigger

**Files:** `src/components/layout/AdminSidebar.tsx` (new client sub-component or
sibling file `AdminMobileNav.tsx`)

**Action:** Build a `'use client'` component wrapping `Sheet` /
`SheetTrigger` / `SheetContent side="left"` from `@/components/ui/sheet`. The
trigger is a `Button variant="ghost" size="icon"` with lucide-react's `Menu`
icon and an accessible label. Controlled open state so a nav link tap sets it
closed. Include a `SheetTitle` (visually hidden if the design has no visible
header) — the underlying Base UI dialog needs an accessible name.

Add `data-testid="btn-admin-nav-toggle"` on the trigger per the project's
test-id conventions.

**Verify:** Component compiles; trigger and drawer content render.

**Done:** Hamburger opens a left drawer with Dashboard, Users, email, logout.

### T-3: Wire responsive visibility into the dashboard layout

**Files:** `src/app/(admin)/admin/(dashboard)/layout.tsx`

**Action:** Restructure the shell so the desktop rail is `hidden md:flex` and a
mobile top bar carrying the hamburger is `md:hidden`. The layout keeps its
server-component `getUser()` call unchanged — only `user.email` is passed down,
preserving the existing T-05-05-02 constraint. Ensure `<main>` retains
`min-w-0 flex-1` so content still shrinks correctly.

**Verify:** `npx tsc --noEmit` (or project typecheck) passes; `npm run lint`
passes; `npm run build` succeeds.

**Done:** At <768px the rail is gone and the hamburger is present; at ≥768px the
rail is present and the hamburger is gone.

## Must-haves

- Desktop (`md`+) admin layout is visually unchanged.
- Mobile shows no 256px rail; nav is reachable via hamburger.
- Logout and admin email remain reachable on mobile.
- No new dependency added (`sheet.tsx` and `lucide-react` already present).
- Server/client boundary preserved: layout stays a Server Component, only the
  drawer is `'use client'`.
