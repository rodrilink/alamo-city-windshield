# Summary: Collapse the admin sidebar on mobile

## What changed

The `/admin` shell rendered `AdminSidebar` as a permanently visible 256px
`<aside>` in a `flex min-h-screen` row. On a phone that rail consumed most of
the viewport and squeezed the dashboard charts and users table into an unusable
column, with no way to dismiss it.

Below the `md` breakpoint the rail is now hidden and the same navigation is
reached through a hamburger button in a compact top bar, which opens a left
slide-in drawer. At `md` and up the layout is unchanged.

## Files

| File | Change |
|------|--------|
| `src/components/layout/AdminSidebar.tsx` | Extracted the nav/email/logout markup into a new exported `AdminSidebarNav` shared by both viewports; added optional `onNavigate`; the rail is now `hidden md:flex`. |
| `src/components/layout/AdminMobileNav.tsx` | **New.** `'use client'` hamburger + `Sheet side="left"` drawer, controlled open state, closes on nav tap, `sr-only` `SheetTitle` for the dialog's accessible name. |
| `src/app/(admin)/admin/(dashboard)/layout.tsx` | Shell restructured to `flex-col md:flex-row`; added a `md:hidden` header holding the hamburger; `<main>` keeps `min-w-0 flex-1`. |

## Decisions

- **Hamburger + drawer** over an icon-only rail (would drop the admin email and
  need new iconography) or a horizontal top nav (does not scale past two links).
- **Markup extracted rather than duplicated** so the desktop rail and mobile
  drawer cannot drift. Only one is mounted per viewport, so the existing
  `data-testid` values still resolve to exactly one element per page.
- **No new dependency.** Reused `src/components/ui/sheet.tsx` and
  `lucide-react`, following the `SheetTrigger render={...}` pattern already
  established in `src/components/layout/TopNav.tsx`.
- **Server/client boundary preserved.** The layout stays a Server Component so
  its `supabase.auth.getUser()` JWT revalidation is untouched; only
  `AdminMobileNav` is `'use client'`, and only `adminEmail` crosses the
  boundary (T-05-05-02).
