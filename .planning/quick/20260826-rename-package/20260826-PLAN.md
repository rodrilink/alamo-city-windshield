# Quick Task: Rename the project package

## Problem

`package.json` still carried `"name": "nextjs-scaffold"`, a leftover from the
initial Next.js scaffold. It appeared in npm script output, `npm ls`, and any
tooling that reads the package identifier.

## Scope

Three occurrences across two files:

- `package.json` — the `name` field
- `package-lock.json` — the root `name` and `packages[""].name`, which must
  stay in sync with `package.json` or `npm ci` warns about a mismatched lock

Out of scope:

- `.planning/phases/01-foundation/01-01-SUMMARY.md` mentions
  `/tmp/nextjs-scaffold` as a historical record of how the project was
  scaffolded. That is an accurate account of a past event, not a live
  reference — rewriting it would falsify the record.
- User-facing branding needed no change: `SITE_NAME` and `BUSINESS.name`
  already read "Alamo City Windshield Repair".

## Tasks

### T-1: Replace the name in both manifests

**Files:** `package.json`, `package-lock.json`

**Action:** Replace the three `"nextjs-scaffold"` string occurrences with
`"alamo-windshield-landing-page"`.

**Verify:** JSON parses; `package.json` name, lock root name, and
`lock.packages[""].name` all agree; `npm ls --depth=0` reports the new name.

**Done:** No live `nextjs-scaffold` reference remains.

### T-2: Verify the gate

**Action:** `tsc --noEmit`, `lint`, `test`, `build`.

**Done:** All four pass.

## Must-haves

- `package.json` and `package-lock.json` names stay in sync.
- The historical `.planning` reference is left intact.
- No user-facing string changes.
